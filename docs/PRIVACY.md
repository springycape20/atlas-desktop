# Privacy and local data

The **Activity** launch page combines existing local task, approval, project and provider-health records. Local records refresh only while the page/app is visible. Provider allowance checks run when Activity opens and once a minute while visible, using supported provider interfaces. Claude checks use the unmodified Claude Code CLI built-in structured `/usage` report with hooks, tools, MCP servers and session persistence disabled. ATLAS does not read Claude sign-in tokens or scrape account endpoints. Unknown/stale limits remain labelled. Opening a task or approval view never resumes work or grants permission. The Activity overview adds no remote service or publisher telemetry.

The development checkout's [usability improvements](USABILITY-AND-POWER.md) use existing local project/task/chat records. Task titles, archive flags and attention-dismissal state are saved with managed task records. Dismissing or archiving retains evidence and can be reversed; task retention limits still apply. Workbench width is stored in local browser storage. Explicit project-file references become ordinary attachment snapshots; editor selections become unsent prompt text. Explicit vault-note selections remain read-only references, require a fresh per-chat preview and create no note cache. Changing the note selection invalidates its review receipt. Provider retry and workflow actions prepare unsent drafts and grant no extra permissions. The embedded preview retains the existing isolated session, origin restrictions and device/download denials.

Optional **Library → Semantic solution search** previews up to 100 completed tasks (at most 4,000 characters each and 200,000 total), then requires explicit approval before sending their prompt/result text to a user-configured HTTP loopback `/v1/embeddings` endpoint. Searches also send the question to that endpoint. ATLAS adds no cloud fallback, model download or publisher service. A local embedding server can have its own cloud routing, logs and retention; review its configuration. Vault notes, source files and attachment bytes are excluded. Up to four vector indexes and four review receipts live in process memory only. Clear all semantic indexes removes those records and invalidates in-flight results; an already dispatched local request may finish. App restart clears all indexes. A source task removed or changed after indexing is omitted from results. Any provider-shared context already recorded in a completed task's text can still be present in the reviewed task excerpt.

Project setup detection reads guarded local manifests and probes tool paths; it runs no project commands. Saving selected commands does not enable automatic checks, setup or preflight. Existing settings on an edited profile are retained. Saved profiles and workflows follow the existing backup/reset behavior.

The optional **Library → Markdown vault** source reads a user-selected dedicated local Markdown folder, including Obsidian vaults, without modifying its files. It defaults to unconfigured; choosing/changing a folder starts disabled. Enable it globally and opt in for each Chat/Colab chat in **Context**, then refresh and review the excerpts before sending. Configuration/preview makes no provider request. Sending shares only bounded relevant excerpts, under existing request and sensitive-context controls. Note links, embeds and frontmatter never grant permissions or execute instructions.

Vault scans have separate bounds and filtering, preserve private paths and integration denials, refuse symlinks/junctions and UNC roots, and keep no note cache. Preview receipts contain only hashes and review identities in bounded process memory. The selected path, enabled flag and root identity are local plaintext metadata in `markdown-vault.json`, included in managed backups and local-data reset. The vault's files remain outside those managed records. Sent excerpts may appear in local task/provider records and provider-retained sessions under their existing retention rules. Disable/remove stops future indexing and inclusion and blocks subsequent provider calls in tasks using the old source; a call already in progress may finish. Removing the source never deletes notes or erases previous disclosures. See [Markdown vault setup and limits](PROJECT-TOOLS.md#optional-markdown-vault-including-obsidian).

The 0.11.0 [execution controls](EXECUTION-CONTROLS.md) store project budget policies, task counters, trial-promotion undo text and benchmark definitions/results locally. These managed records enter backups and local-data reset. Benchmark reports can contain task text, check commands and project paths; exports are explicit and are not automatically redacted or uploaded. Running an approved benchmark sends its fixed cases to your provider accounts and can incur usage. Opening or saving a suite sends nothing. Promotion changes selected files only after review and approval and retains bounded local undo records. No publisher statistics collection is added.

The 0.11.0 [background backups and saved visual references](BACKUPS-AND-VISUAL-BASELINES.md) allow automatic copies in a user-chosen external folder. Those copies survive local-data reset; the default copies inside ATLAS data are removed. Saved visual baselines contain screenshot bytes, project paths, names, page URLs and hashes in a local managed JSON record. They enter record backups and local-data reset and are not uploaded automatically. Backup archives remain unencrypted.

From 0.10.5, automatic backups are on by default: once a day ATLAS writes a copy of its managed records to `auto-backups` in the ATLAS data folder and keeps the newest seven. They are compressed, not encrypted, and may include confidential records, so an older copy can still hold something you have since deleted from ATLAS. Turn them off in **Backups and recovery**, which leaves existing copies in place. Delete local ATLAS data removes them. **Report a problem** opens a blank GitHub issue and sends nothing itself; anything you paste into that issue is public.

The 0.10.2 [power-tool additions](POWER-TOOL-UPGRADES.md) save installed-language-server configuration and browser recipes (including any fill values) locally as plaintext. These records join managed backups and local-data reset. Approved language servers run with the user's account permissions and may independently access files or networks. Browser checks run only after confirmation against the selected local preview. Screenshot/profile baselines and bounded console evidence stay in preview memory unless explicitly attached or copied into a draft; sending that draft shares its included evidence with the selected provider. No publisher collection is added.

The 0.10.1 [work-session features](WORK-SESSIONS.md) store project snapshot bytes, trial copies, path/hash receipts, requirement notes and inbox dismissals locally. No publisher collection is added. Source snapshots and metadata enter managed-record backups; trial working folders do not. Export wanted trials to your own project folder before resetting ATLAS data, which removes managed trial folders and the new local records. Offline preparation makes no model request; explicitly approved check commands can access the network. A reviewed handoff or preparation draft reaches a provider only when you send it. Bug reports are user-reviewed local exports, with raw output excluded by default; redaction is heuristic and does not guarantee anonymity.

The selected power upgrades in ATLAS 0.10.0 add optional local backups, saved service/API definitions and document text extraction. Backups are compressed, not encrypted, and may include confidential records. API sends contact your chosen endpoint after confirmation; one-time headers are not saved, while request URLs/bodies are. Interactive PTY terminals use session-level approval for raw input. Sensitive-context review is heuristic, and integration access declarations are informational. There is no publisher telemetry. See [Selected power upgrades](SELECTED-POWER-UPGRADES.md) for retention, restore scope and limits.

In ATLAS 0.10.0, completion-time evidence archives store bounded diffs, task titles, check output and reported usage locally. Archives remain until individually deleted under Tasks → Saved task evidence or current app data is reset. Project intelligence runs in the local index worker; related excerpts reach providers only through enabled chat context. Managed terminal commands and approved repair checks run with your account permissions and can access files or networks. Terminal command/input approvals and bounded repair-loop controls do not create a publisher reporting service. See [Deeper project workflows](DEEPER-WORKFLOWS.md).

ATLAS 0.10.0 includes a sandboxed local-site preview and optional screenshot feedback. The preview blocks requests outside its selected local origin. Starting a development server requires confirmation because project configuration runs with your account permissions and may itself access the network. Captures become local attachments and are sent to a provider only when you send the message. Named checkpoints store eligible project text locally and exclude private and denied paths. See [Project workbench](PROJECT-WORKBENCH.md) for limits and controls.

## What leaves your computer

When you send a message, selected prompts, attachments and relevant task/context information go to your chosen AI provider through its installed CLI and your own account. Colab shares relevant task work and handovers between Codex and Claude. Desktop tools may return screen images, clipboard content or file contents to the requesting provider. These can contain confidential information; review what is visible and attached before granting control or sending a request. Each provider's terms, retention settings and charges apply. ATLAS is not affiliated with or endorsed by OpenAI or Anthropic.

Whisper recognition runs on your PC, and Windows speech uses voices available on your system. Bundled Kokoro was removed in 0.8.3. Continuous wake-word and automatic follow-up listening are off until you enable them in Settings. Older default-on settings require renewed opt-in. A manual microphone press records a voice request; recognised text may be sent as a prompt. The wake indicator pauses automatic listening. Consider others nearby and obtain any required permission before recording them. Audio is handled transiently in memory and sent to the local Whisper process for recognition; ATLAS does not intentionally save microphone recordings as history.

Optional ElevenLabs speech sends the spoken-answer text to ElevenLabs using your API key and plan. It is a cloud service, even though other ATLAS records are local. ATLAS uses Windows secure storage for the saved key and does not read Claude sign-in tokens to display usage.

At startup ATLAS checks GitHub for updates and asks installed providers for available models through supported interfaces. Downloads contact GitHub, Hugging Face and runtime/package hosts when the relevant feature is used. Those hosts receive normal network metadata such as an IP address. Custom MCP servers and programs you authorise have their own behaviour and may make other requests; only enable ones you trust. The publisher does not receive those requests through an ATLAS server.

The 0.11.0 **Automatically download updates** preference is off by default. Enabling it allows release-installer downloads from GitHub after launch checks, without another download click. Turning it off stops future automatic downloads; an in-progress transfer can finish. Update availability is announced once per version per launch. No publisher telemetry is added, and ATLAS still asks before restarting to install.

## What stays locally

ATLAS 0.10.0 can preview project images, text and static HTML locally in the chat window. Previewing does not send the file to a provider. Static HTML previews disable scripts, forms and network requests and use bounded local image/stylesheet reads. **Attach to next message** creates a local attachment copy through the existing flow; sending that message may share it with the selected provider. Static file previews do not start a development server or execute project code; the separate live-preview controls require an explicit action.

In Project tools, source excerpts are indexed in a bounded in-memory worker cache and are added to provider requests only when enabled for the chat. A basic file-name map can be saved locally. Context exclusions affect ATLAS additions and do not change provider filesystem permissions. Custom workflow templates and batch/task records stay in the current ATLAS data folder; they can contain task text and command names. Parallel batches make multiple provider requests and share subtask work in the combined review.

Optional local-model text chat sends selected text to a user-configured loopback API and never automatically falls back to a cloud provider. That local server may have its own cloud routing, logs and retention; choose an installed local model for offline inference. Optional ElevenLabs speech and GitHub update checks remain separate. ATLAS does not bundle or download additional language models for this feature.

Saved chats, project/global memories, editable task plans, environment recipes, reminders, settings, permissions, copied attachments and task records are principally under `%LOCALAPPDATA%\ATLAS`. Colab history uses Chromium IndexedDB. Some migration copies may remain under `%APPDATA%\atlas-local-desktop`. Project worktrees and Git recovery snapshots can be stored in or alongside your projects. Provider CLIs keep their own history separately.

Conversation and attachment stores are not encrypted by ATLAS. Windows account permissions and any device encryption protect them to their respective limits. Local malware or another process running as you may access them. Saved ElevenLabs keys use Windows-backed encryption; that is not protection from all software running under your account.

ATLAS keeps data until you delete it; uninstalling preserves it for reinstall. Settings → Tools and data → Delete local ATLAS data requests a confirmed restart, then deletes current ATLAS chats, attachments, memories, settings, permission grants, logs and browser storage before stores reopen. It keeps downloaded tool runtimes and prevents automatic reimport of legacy records. Old Kokoro model caches within the current data directory are deleted by this reset. It does **not** delete legacy folders, your project files/worktrees, Git recovery snapshots, exported files, provider histories, or copies already received by providers. Remove those separately if desired. File deletion is not a promise of forensic secure erasure from disks or backups.

Diagnostic logs remain local unless you share them. Export redacted diagnostic log removes recognised credential patterns, but cannot identify every private sentence, path or screenshot. Review exports before sharing; never post raw credentials or chats in public issues. Support messages you choose to send to GitHub or a maintainer are a separate disclosure.

In ATLAS 0.10.1, automatic completion-check logs also stay in the ATLAS data folder, up to 4 MiB per command. These raw logs can contain project data and are not automatically redacted; the in-app preview is limited to 64 KB. Reviewed milestone packets store selected task summaries, constraints, file names and check results locally in `milestone-handovers.json`, with up to 100 bounded packets. They are included by local managed-record backups and removed by local-data reset; exported backups remain separate. Opening a handover only creates an unsent draft. Sending that draft shares its contents with the selected provider. Unchanged-reference receipts are held only in process memory. Optional stronger-model repair sends the task and focused check evidence in an additional provider call under the normal permissions and sensitive-context review.

## Choices and limitations

Version 0.11.1 adds local workspace snapshots (file paths, preview origin/path and terminal layout), optional reviewed browser recipes and chunked history storage. Recording starts only after approval, excludes likely private fields heuristically and should use test data. Debugger output and inspected values stay local unless you separately copy/share them; debugged project code has its own filesystem/network access. Assistant retains its legacy migration file and unreferenced message chunks for recovery. Managed backups and local-data reset include the new chunk directory; exported backups remain separate. See the [project tool boundaries](PROJECT-TOOLS-NEXT.md).

You can type instead of using a microphone, choose local speech, remove a saved ElevenLabs key, revoke screen/shell permissions per chat, stop tasks, export chats, and reset current app records. AI replies can be wrong. A reviewer acceptance or passing test is evidence about the reported review/checks, not a guarantee that an answer is correct. A project worktree and remembered command permission are not an operating-system sandbox. Do not enable provider approval bypass for untrusted work.

This explanation describes the application, not every third-party CLI's internal traffic. There is no blanket waiver of rights that Australian law does not permit to be excluded. The publisher should reassess this statement before adding hosted features, analytics, support uploads or a website with data-collection features. Updated: 13 November 2026.

Saved working sessions are explicit local browser-storage snapshots per project (50 maximum). They include file paths, local preview addresses and terminal definitions. Unsent chat/editor text is included only when the save checkbox is selected; chat drafts and each changed editor draft are limited to 128,000 characters. Preview URL query strings, fragments and credentials are excluded. Drafts remain local until a normal send/save action. Restore preserves conflicting current drafts and does not execute commands, start a preview server, or replay terminal output. These renderer records follow existing backup/reset behavior.

Optional Git checkpoints create local `refs/atlas/checkpoints/` references using Git stash-create without changing HEAD or staged/working contents. Git retains tracked contents, including tracked private files, under the repository's existing Git storage policy; eligible untracked text is covered by ATLAS's separate bounded snapshot and exclusions. Named snapshots follow ATLAS backup/reset; Git objects/references stay in the external project and are not part of an ATLAS data backup. File restores retain the existing selected-file preview, later-edit checks and recovery snapshot. Creating a checkpoint grants no provider permission.

Allowance warnings use only fresh reported main meters (10% remaining or less, reported within five minutes); they are not cost estimates. Unknown/stale readings cause no invented warning or automatic routing. Switching providers requires a native choice before dispatch, including usage-limit handoffs that previously selected a fallback automatically. The chosen provider receives the existing selected context under its usual permissions. Unified search adds local project/workflow results and project/type filters; project-file search remains opt-in and vault-note caching is unchanged.

New installations start with spoken replies, wake-word listening and automatic follow-up listening disabled. Missing speech settings remain off when settings are saved. Users can opt in through Settings, or start a single recording with the microphone button. Existing explicit saved voice preferences are preserved; changing speech settings does not silently enable microphone features.

Assistant unsent drafts now autosave locally per chat and project, up to 30 drafts, 128,000 characters per draft and 512,000 total. They are plaintext renderer records included by existing backup/reset handling; older entries are evicted to maintain the bounds. Sending removes the recovery copy. Colab retains its existing chat-draft persistence; this does not create a vault index or read source notes. Background result-read timestamps retain up to 500 chat markers locally. Bulk cleanup stores up to 10 in-memory Undo receipts for five minutes; it preserves task evidence and never resumes or approves work. Error cards expose bounded diagnostic text only after expansion and redact common bearer/API-key forms; that is not a guarantee of complete secret detection.
