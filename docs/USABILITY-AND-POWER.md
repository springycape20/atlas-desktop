# Usability and power improvements

Implementation checklist for the requested ten improvements. Each item is reported complete only after its targeted checks pass.

- [x] Project home — project-scoped recent chats, running tasks, attention and approvals; settings remain available.
- [x] Task centre — separate Active, Needs attention and History; project/text filters, saved titles and direct task actions.
- [x] Visible composer context — per-chat source indicators, counts, exclusions and preview status; edits invalidate vault receipts.
- [x] Connected workbench — persistent editor/terminal panels, sandboxed embedded local preview, task changes and adjustable width.
- [x] Actionable provider failures — known cooldowns, connection help, reviewed model handoff and unsent provider-specific retry drafts.
- [x] Task completion screen — model report, executed checks, changed files, referenced outputs and review/follow-up actions.
- [x] Direct context references — file/note/code picker, composer shortcuts and editor-selection drafts.
- [x] Optional local semantic solution search — reviewed completed-task text, local embedding endpoint, in-memory indexes and stale-source omission.
- [x] Save successful task as workflow — editable task/criteria/checks with reusable parameter inputs.
- [x] Project setup assistant — guarded manifest detection, prerequisite availability and reviewed profile saving without execution.

The project home answers “What should I continue or review in this project?” The task centre answers “What is running or needs my attention?” Both use retained local records. The existing ATLAS typography and palette are retained; flat lists and task evidence provide the screen's identity. Empty and unavailable records are displayed explicitly. No model calls or command execution occur when either screen opens.

These features ship in ATLAS 0.12.0. See the release review for packaging checks and material limits.

## Where to use each feature

**Activity is now the launch page.** Its sidebar entry and Ctrl+K destination return to the overview at any time. It shows tasks requiring attention, tasks working now, recent results, completed-task counts for the preceding 24 hours and provider usage/availability. Project filtering follows original project folders for isolated tasks. Decisions open the existing approval view; task/result links open existing work or evidence and never resume or approve anything automatically. Chat and Colab retain drafts and reading positions when visiting Activity.

Activity refreshes local records every five seconds while visible and responds to task/approval events. Leaving the page or hiding the app stops periodic refresh. Supported provider usage is checked on opening and once a minute while Activity is visible. **Refresh provider usage** also requests supported account limits manually. Missing allowance remains unavailable; stale data and passed reset times are labelled. Claude's account-page link remains available without reading sign-in tokens. Activity covers retained ATLAS tasks, not every session in other applications. It adds no cross-device service, telemetry or additional persisted state.

The launch page answers “Does anything need me, and what should I continue?” Attention comes first, active work second and recent results third. Provider status and existing workflow shortcuts sit alongside the work at desktop widths and stack below it in narrow windows. The ATLAS mark, typography, theme and sidebar are retained. Counts come from retained records rather than illustrative activity totals. Detailed task management stays in Task centre; Activity links to it rather than duplicating its editing controls. Dark, light, high-contrast and enlarged text use the same information hierarchy.

## Boundaries and recovery

Project/task lists reflect retained records, not every past provider session. A completed task with failed checks appears under Needs attention. Model completion is not proof that requirements passed. Task result reports show a bounded 16,000-character excerpt; open the source conversation for the full output. Up to 20 referenced output links are offered, with path access checked on use.

Explicit note selection changes the eligible set; it does not override private/denied paths, links, scan limits, byte budgets, per-chat opt-in or stale-content checks. The vault remains read-only with no retained note cache. Use relevant notes instead in Context to clear explicit selections. Prompt-injection defenses remain heuristic and do not replace tool permissions.

Semantic search indexes only completed task prompt/result text. The index is bounded to 100 tasks, 4,000 characters per task, 200,000 total characters and four retained in-memory indexes. Builds use batches of 16; each loopback request times out after 30 seconds with a 2 MiB response cap. Embeddings must contain finite nonzero vectors with 2–4,096 dimensions and consistent size. Preview receipts expire after ten minutes and bind the exact source set. Changed/deleted tasks are omitted until rebuilding. No embeddings or endpoint/model settings are saved by this feature. A local server is required; ATLAS does not install one or validate its independent network policy. See [Privacy](PRIVACY.md).

Setup suggestions are manifest-derived names, not verified commands. Tool availability is a PATH check, not a version guarantee. Review commands before enabling their separate execution settings. Existing profiles retain prior execution preferences; saving the setup form alone does not run anything.

## Further task improvements

- **Allowance-aware starts:** fresh main usage meters at or below 10% trigger a native cancel/continue choice before dispatch. Assistant can offer an available alternative only when all its reported main meters are above the threshold. Readings older than five minutes, stale values and elapsed windows are not used. Cooling-down provider switches and usage-limit fallback now need explicit consent. Cancelling before dispatch restores the unsent prompt when the composer is empty. Colab warns for both providers and retains its role choices.
- **Saved working sessions:** Tasks → Saved workspace saves project-specific tabs, active file, workbench panel/width, sanitized loopback preview address and terminal definitions. Opt in to include unsent chat/editor drafts. Restore working session reapplies drafts without sending/saving them; different current drafts and changed disk versions are protected. Review saved editor drafts exposes retained text when automatic restore is refused. Open saved conversation returns to the matching chat. Preview and approved shell starts remain separate explicit actions; no commands or shell process state are replayed.
- **Task handoffs:** Task result leads with tracked changed-file counts, actual passed/failed checks, unresolved evidence and a next action. The existing diff, check detail, original model report and conversation links remain available. A model claiming tests passed never becomes executed evidence.
- **Unified work search:** Ctrl+Shift+F / Library → Search all work now includes project profiles and workflows alongside retained tasks, messages, transcripts and memories. Type/project filters narrow results; project identity includes isolated tasks' original folder. File excerpts remain opt-in. Results open their source project, workflow review, task, chat or editor file.
- **Activity cleanup:** stopped tasks can be dismissed from attention or archived from Activity/Task centre. Task centre → History restores dismissed attention; Archived contains an unarchive action. Active tasks and pending approvals cannot be hidden. New failure details invalidate a dismissal. Evidence is preserved under existing task retention rules; this is not a permanent task archive.
- **Before-task Git checkpoints:** the composer Add menu contains “Checkpoint before next task”. It creates a one-shot named Git checkpoint before dispatch; failure leaves the prompt and choice intact. Tasks → Named checkpoints also offers Create Git checkpoint and Git summary review. Requires a repository root with an existing commit. Git preserves tracked content; a separate bounded local text snapshot also captures eligible untracked files. HEAD, index contents and working files stay unchanged. Reviewed selected-file restoration preserves later-edit protection and saves recovery snapshots. Git refs live in the project rather than ATLAS backups.

Design: true-black-flat, seed 525134394, retaining ATLAS's established palette/type and component shell. No redraws. The product-specific evidence is each task's executed-check handoff and checkpoint identity; no illustrative figures or new ornamental panels were added. Each screen answers the existing project's continuation/review question.

## Everyday polish

- Error responses now show a short explanation and a connection, usage or task-review action. Expand Technical details for bounded, credential-redacted diagnostics. No action retries a task automatically.
- Assistant drafts recover automatically per chat and project using local browser storage. Saves debounce by 250 ms and flush on navigation, hiding or closing. Sent drafts are removed. Up to 30 drafts, 128,000 characters each and 512,000 characters total are retained; older drafts are evicted to respect these limits. Unavailable storage is reported without preventing chat. Colab continues to use its existing persisted per-chat drafts. Editor-draft recovery remains opt-in through Saved workspace.
- Embedded fenced text shows its language/type and offers Expand/Collapse for long blocks. The header and copy control remain reachable while scrolling inside the box. Copy preserves the exact body without the fence or label.
- Chat and Colab sidebars show Running, Needs approval, Needs attention or New result from retained task and approval records. Read markers are local and bounded to 500 chats. Existing historical results are not all marked new on the first launch.
- Activity usage windows show relative reset countdowns, with exact Australian/Sydney dates on hover. Related provider activity and chat timestamps use Australian dates. Unknown and passed reset times remain explicit.
- Activity can archive or dismiss several selected stopped tasks. All selected tasks are validated before any change; active tasks and pending approvals block the batch. Undo is available for five minutes in the current app process, with at most 10 receipts. Undo refuses tasks changed since the cleanup. Individual restore controls remain in Task centre.
- Tool buttons, headings, action gaps, error panels and text-box headers now share consistent spacing and sizing, preserving the existing ATLAS palette, type and compact navigation.
