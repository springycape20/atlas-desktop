# ATLAS 0.9.1 technical release review

Prepared 29 October 2026 for the owner's requested patch push. This records technical verification, not legal advice or certification. The release PR requires passing CI and the owner's confirmation before merge/tag/publication under the repository handover rules.

The only production package change from 0.9.0 is the MCP SDK's transitive `@hono/node-server`, from 1.19.17 to 2.1.5, approved by the owner on 29 October. It retains the MIT licence and satisfies the SDK's declared version range. Its Node >=20 requirement is compatible with the bundled Electron runtime. The update resolves [GHSA-rmxm-3fg6-px4f](https://github.com/advisories/GHSA-rmxm-3fg6-px4f); the production advisory check reports zero vulnerabilities. No new dependency is added. The exact lock hash is recorded in `legal/release-review.json`. Removed Kokoro/eSpeak/ONNX/sharp dependencies remain excluded. Required notices, pinned speech resources, private-path exclusions, fuses, ASAR integrity and updater hashes remain mandatory. The existing owner-approved unsigned policy is retained; no signing or legal approval is claimed.

Project file previews enforce canonical root containment, private/denied path exclusions, bounded reads and explicit attachment actions. Static HTML disables scripts, forms and network access. The live preview uses a separate sandboxed BrowserWindow/session without a preload, Node integration or ATLAS API. It denies device permissions, downloads, popups and requests outside its chosen local origin. HTTP loopback only is accepted; same-origin WebSockets support development reload. An explicitly approved Vite server executes project configuration and plugins with the user's account permissions and can itself access the network. Other frameworks require a separately started server. No dependency is installed by the feature.

Screenshot capture checks the active project and prepares attachments/draft text without sending. Page selectors and text remain untrusted page-reported material. Named checkpoints exclude private and denied paths and use the existing bounded text tracker, selected-file review, stale-change checks, explicit restore confirmation and recovery snapshots. They are not complete backups. Context size uses a labelled character-based estimate; provider-managed compaction is not exposed. Health checks detect presence and suggest commands without executing project scripts or network audits. Privacy and feature documents describe these limits. There is no new publisher server, telemetry or bundled model.

Validation includes 457 tests, eleven isolated Electron UI suites, formatting and diff checks, and a locally built installer/package verification. Tests use fake providers and local fixture servers, not real provider accounts. UI preview tests check real sandbox isolation, cross-origin blocking, denied camera permission, element selection, screenshot capture and project ownership; process tests cover server approval and fixed loopback arguments. GitHub CI and release verification remain required. These checks are not an independent penetration test or guarantee of safe model output.
