# ATLAS 0.9.0 technical release review

Prepared 29 October 2026 for the owner's requested public release. This records technical verification, not legal advice or certification.

The production dependency graph is unchanged from 0.8.3: the lockfile differs only in the two root version fields. A fresh production advisory check reports zero vulnerabilities. The exact new lock hash is recorded in `legal/release-review.json`. The removed Kokoro/eSpeak/ONNX/sharp chain remains absent. Existing notices, pinned speech resources, private-path exclusions, binary fuses, ASAR integrity and updater hashes remain mandatory in release verification. The prior unsigned-release decision is retained; Windows warnings are expected and no authenticated publisher or signing approval is claimed. Historical distribution questions documented in `PATCH-RELEASE-REVIEW.md` remain separate.

0.9.0 adds no publisher server, telemetry, production dependency or bundled language model. Source indexing stays bounded and optional for prompt excerpts; context exclusions are not filesystem permissions. Local-model mode uses a loopback server, which may itself have cloud routing. Plans, memories and recipes are plaintext local records included in local reset scope. Project memories are matched to an exact canonical folder. Provider history remains local transcript history, not private web-chat access. Privacy and feature documentation describe these limits.

Environment recipes are user-configured commands shown for explicit approval before execution in isolated editing Colab workspaces. Saving runs nothing; Plan/Compare skip setup, cancellation is respected and failed setup stops later commands and model work. Recipes may execute project code or download packages. Plans require revision approval before preparing an unsent draft, which still uses normal workspace/permission checks. Model-tier routing is opt-in and heuristic; hardware and duration estimates are labelled and do not promise performance or completion. The review centre uses the existing conflict-checked restore and workspace-review APIs.

Local validation passed 449 unit tests and nine isolated Electron UI suites, without real provider accounts or new installations. The feature package was built and verified locally; the versioned 0.9.0 installer and GitHub CI must pass before the release tag is published. Package verification now explicitly checks the new runtime modules. These checks are not an independent penetration test, legal opinion or guarantee of safe model output.
