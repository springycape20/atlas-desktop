# Model usage efficiency

ATLAS cannot extend provider limits or guarantee a number of extra working hours. It can avoid sending unnecessary context and avoid model passes that add little value. Usage reports are provider-reported where available and estimates otherwise; they are not Claude subscription-quota measurements.

## Controls available in 0.10.0

- Use Assistant for a small, clearly scoped change. Use Colab when independent build/review passes are useful. Choose Economy or Balanced and a sensible pass limit; reserve Thorough for difficult tasks.
- In Context, include only the files, memories and history relevant to the task. Use the ranked-context preview to understand selections. Attach selected PDF page text and remove the original document when only those pages are needed.
- Run searches, Git inspection and test commands locally. Supply the failing check and relevant error excerpt rather than a complete successful log. ATLAS runs configured checks before Colab review, so failures can return directly to the builder.
- Write a compact task with acceptance criteria and the required output format. Keep durable project rules concise, and avoid attaching generated folders or repeating the same background in every turn.
- For unrelated work, start a new chat with the relevant project memory or a reviewed handover. Starting fresh without that handover can lose decisions, so use it at a meaningful milestone.

These practices align with the [official OpenAI guidance](https://learn.chatgpt.com/docs/pricing): keep prompts precise, remove unnecessary context and limit source material to relevant files. Provider-specific billing, credits and subscription limits still apply.

## Controls added in 0.10.1

The following five controls are included in ATLAS 0.10.1. The older 0.10.0 release does not include them.

1. **Request context budget:** open **Context → Refresh preview** before sending. The breakdown includes your current request, selected instructions, memories, recent history, attachments and project excerpts. It counts selected images but labels their token cost unknown. Text uses four characters per token; provider instructions, retained session history, tools, reasoning and exact pass counts remain unknown. The 16,000-text-token threshold is a planning warning, not a provider limit or spending cap.
2. **Unchanged reference reuse:** **Models → Configure model routing** controls reuse, enabled by default. Assistant replaces unchanged attachment/project reference blocks with small reminders only after a backend-confirmed retained session has previously received those exact hashes successfully. Requests, project instructions and memories are always included. Provider/model, folder, settings and context scope separate receipts; unknown, changed, failed and restarted sessions use full references. Full refresh occurs after five turns or 15 minutes. Turn reuse off to resend full references. Provider compaction remains provider-managed, so a model may need to read a referenced source again. This is not an API cache-discount feature.
3. **Check-driven model escalation:** in that same panel, enable automatic tiers, configure distinct Fast and Strong IDs, and optionally enable **one stronger-model repair**. This is off by default and may use extra tokens. It applies only to Assistant automatic routing that actually chose the fast model, changed files and returned executed checks with a failing nonzero exit. It excludes project pins, manual tiers, read-only/local work, cancellation, timeouts and existing manual repair workflows. The repair starts with full context in a fresh provider session and reruns the same configured checks once. A failure remains a failure; no unlimited escalation loop occurs. Colab retains its existing builder/reviewer workflow.
4. **Reviewed milestone handovers:** open **Tasks → Milestone handovers**. Create a local editable packet from a finished retained task, review its goal, decisions/constraints, changed files, actual checks, unresolved issues and next steps, then explicitly mark it reviewed. Saving edits invalidates review. Open a fresh Assistant or Colab draft; nothing sends automatically, the source chat stays intact and no provider session is copied. A changed/missing project profile or an existing unsent draft blocks replacement. Keep essential constraints in the packet and review current project instructions before sending. Packets are capped at 100 local records, with bounded fields and a 19,000-character draft limit.
5. **Focused check evidence and local logs:** Colab failure feedback and repair prompts use relevant failure lines or structured failed-test details, bounded independently of successful log noise. Check command/status/exit summaries remain visible. New automatic completion checks record up to 4 MiB per command in local managed storage; task history keeps its existing bounded output. **Tasks → Check logs** previews the first 64 KB or reveals the saved file. Log recording and previews disclose truncation; older tasks and some manually run commands may have no saved log. These logs may contain project data and are never uploaded by a publisher reporting service. Provider-native tool output is still controlled by the provider.

Shorter prompts do not guarantee lower total usage. Compare completion quality, check results, retries and provider-reported usage; repair passes or rereading sources can outweigh saved context. No feature measures remaining Claude subscription allowance.

## Further improvement to consider

**Stable reusable prompts:** keep shared instructions and tool definitions stable and put changing task data later. Where the provider interface supports caching controls and reports cache usage, measure the result instead of assuming savings. [Official prompt-caching guidance](https://developers.openai.com/api/docs/guides/prompt-caching) describes prefix matching; API controls should not be assumed to exist in every CLI integration.
