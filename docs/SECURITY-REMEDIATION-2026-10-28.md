# Security remediation status

Prepared 28 October 2026 after approval of the [audit remediation plan](SECURITY-COMPLIANCE-AUDIT-2026-10-28.md). These are working-tree changes on `codex/handover-follow-ups`; no release has been published. Kokoro is retained as the owner requested.

| Finding | Implemented | Remaining limits / external work |
| --- | --- | --- |
| S1: Claude credentials | Removed credential-file/environment-token reading and direct OAuth usage requests. The usage widget links to Claude's own page. Tests assert zero credential reads and network requests. | Ordinary unmodified CLI use retains its own provider terms. |
| S2: shell permission | Reproduced obfuscated-command bypasses; remembered permission now rejects unknown/dynamic/escaped syntax, indirect command names, recognised nested shells and inline interpreter flags. Permission wording states the actual boundary. | A literal project program/script can still modify or delete files. This grant is not a sandbox or a guarantee about arbitrary programs; separate approvals and revocation remain available. |
| S3: licences | Added upstream licence/model texts with provenance hashes, generated dependency/native notice material (including sharp's native README table), npm CycloneDX inventory and exact-source review. Packaging includes these files and verifies their presence. | Exact eSpeak source/build provenance, GPL combined-work assessment and native LGPL/source/relinking review remain unresolved. `legal/release-review.json` remains pending and blocks public tags. Notices alone do not settle these obligations. |
| S4: microphone | Wake/follow-up defaults off; legacy default-on settings require renewed opt-in. Interruption listening also honours opt-out. The wake indicator stops automatic capture and persists the opt-out. Explanations identify provider transmission and bystanders. | State/territory recording circumstances still matter. A software toggle is not universal legal permission to record others. |
| S5: signing/updates | Public-tag preflight requires signing and a verified publisher; release verification requires signatures/publisher configuration. Manual/local unsigned review builds remain possible. | SignPath activation/manual approval and actual-certificate update migration/tamper tests require the real signing setup. No certificate identity or legal approval was invented. |
| S6: claims/disclosures | README qualifies reviewed results and actual checks. Privacy documentation explains provider requests, optional cloud speech, local plaintext records, retention/deletion and support exports. | Lawyer review of final disclosures and the publisher's actual circumstances remains appropriate. |
| S7: data/logs | Confirmed restart-based reset removes current records before stores reopen; protects the fixed data root, handles links without traversing them and prevents legacy reimport. Added redacted log export and redaction of common secrets/private keys in new diagnostic output. | Download caches remain. Project worktrees/Git snapshots, exports, legacy copies, provider history and third-party copies are explicitly excluded. No forensic erasure or blanket encryption claim; local conversation stores remain plaintext. |
| S8: provenance | uv installer now uses a fixed release archive and SHA-256 before extraction. Both actual Kokoro transformer loaders use an immutable model revision; local model lookup is disabled. | The uv installer script was parsed/tested but not executed. Kokoro inference was not downloaded/run in this remediation. The model revision pin does not protect against malware running as the user. |
| S9: package hardening | ASAR integrity and ASAR-only loading enabled in addition to existing fuses. A fresh local package's binary flags and embedded ASAR hash are checked; private-path exclusions and pinned Whisper hashes are verified. | The local review build is unsigned and is not the published installer. Signature/update-transition and independent penetration testing remain external gates. |
| S10: reporting/maintenance | GitHub private vulnerability reporting enabled and verified. Added SECURITY.md and a production advisory CI check; preserved the repository's existing grouped Dependabot setup. | Maintainer triage and ongoing security maintenance require continued human ownership; no response-time promise is made. |

## Verification

- Full unit suite: **423 passing tests**, no failures/skips, including real PowerShell cancellation fixtures and data-reset safety/consent tests.
- Formatting: `npm run format:check` passes.
- Electron checks: Assistant, Settings (including narrow width), approvals, Colab, and release screens pass using isolated demo data; no real provider accounts are used.
- `npm audit --json` during the preceding audit reported zero advisories. This does not cover all native binaries, models or application logic. CI now checks production advisories on subsequent runs.
- Fresh `electron-builder --win --dir` review package built with the existing Electron distribution and dependency rebuild disabled. Approved Whisper resources were downloaded and checksum-verified. `build/verify-package.cjs` checks notices/inventory, private-file exclusions, model hashes, hardened binary fuses and the embedded ASAR hash.
- No installed ATLAS, user chats/settings, provider credentials or public releases were modified by the tests. GitHub private-reporting configuration is the one external repository setting changed.
